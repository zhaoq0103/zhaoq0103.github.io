代理服务器的两种运行方式： 直接代理和反向代理

https的直接代理：

	本地启用代理服务器，代理与要访问的服务器建立pipe,
		然后客户端通过这个管道与服务器进行 tls 握手，
		最后用http进行数据交换。

		从代理的角度看，交换的数据都是tls加密过的。

		这个叫做 HTTP CONNECT tunneling.

		这种情况下， 代理无法查看加密数据，也不一定要求是https服务器，


https的反向代理：（通常用在服务器端）
	 
	 反向代理需要 1)私钥   2)私钥签名过的证书（或者是CA机构 签名，需要付费）

	 从客户端的角度看，要信任反向代理的证书。

	 和直接代理服务器不同的是，反向代理把客户端连接到自己的https服务器，而不是
	 真正的 remote Server.



Intercept HTTPS

# Create the key
openssl genrsa -out ~/.ssh/my-private-root-ca.key.pem 2048
# Create the cert
openssl req -x509 -new -nodes -key ~/.ssh/my-private-root-ca.key.pem -days 1024 -out ~/.ssh/my-private-root-ca.crt.pem -subj "/C=US/ST=Utah/L=Provo/O=ACME Signing Authority Inc/CN=example.com"




Create an HTTPS reverse proxy

# Create the key
openssl genrsa -out ./my-server.key.pem 2048
# Create the certificate signing request
openssl req -new -key ./my-server.key.pem -out ./my-server.csr.pem -subj "/C=US/ST=Utah/L=Provo/O=ACME Tech Inc/CN=localhost"
# Create the cert
openssl x509 -req -in ./my-server.csr.pem -CA ~/.ssh/my-private-root-ca.crt.pem -CAkey ~/.ssh/my-private-root-ca.key.pem -CAcreateserial -out ./my-server.crt.pem -days 500



上面提到的 https直接代理解密的 过程，是基于客户端单向认证服务器端的证书，
我们只需要做一个自签名证书，让客户端认为我们得它要连接的服务器就可以。
服务器对客户端的身份并没有进行验证。




MAC OS 命令行 设置自签名证书：

	echo "输入本地登录密码" 
	&& sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain "/Users/zhaoq0103/DEV/code-github/WeChatVideoDownloader/public/keys/public.pem" 
	&&  touch /Users/zhaoq0103/.wechat-video-downloader/installed.lock 
	&& echo "安装完成"
